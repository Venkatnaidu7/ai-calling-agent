# Phase 8 — Plivo production integration

Plivo is a first-class voice provider alongside Twilio. The application keeps provider-specific credentials and webhook handling on the server; secrets must never be sent from the browser or committed to Git.

## Configuration

Set these server-side environment variables:

```env
PLIVO_AUTH_ID=your_auth_id
PLIVO_AUTH_TOKEN=your_auth_token
PUBLIC_BASE_URL=https://your-public-host.example
```

`PUBLIC_BASE_URL` must be HTTPS for production. The service generates the Plivo WebSocket URL from it and signs the stream URL with the application's `SECRET_KEY`.

## Webhooks

Configure the Plivo number to use these endpoints:

- Inbound answer: `/api/v1/voice/plivo/inbound`
- Outbound answer: `/api/v1/voice/plivo/outbound/{call_id}` (generated per call)
- Ring callback: `/api/v1/voice/plivo/ring`
- Hangup/status callback: `/api/v1/voice/plivo/status`
- Stream status callback: `/api/v1/voice/plivo/stream-status`
- Bidirectional audio WebSocket: `/api/v1/voice/plivo/stream/{call_id}` (generated by the API)

The Plivo provider validates V3 webhook signatures when a Plivo auth token is configured. Production fails closed if the token is missing. WebSocket connections also require the Plivo V3 signature and an application-bound HMAC stream token.

## Audio path

The live call path is:

`Plivo PSTN -> bidirectional WebSocket -> FastAPI -> OpenAI Realtime -> FastAPI -> Plivo`

Audio uses 8 kHz μ-law (`audio/x-mulaw`), matching telephony requirements and the current OpenAI Realtime PCMU bridge. Speech interruption cancels the active model response and clears queued provider audio so the caller can take the turn naturally.

## Call lifecycle

Provider callbacks update the shared `Call` model using the same normalized states used by Twilio. Terminal calls enqueue Call Intelligence asynchronously. Callback processing is designed to tolerate duplicate provider notifications by checking terminal state before scheduling terminal work.

## Phone numbers

A Plivo number is represented by the existing `PhoneNumber` model with `provider="plivo"`, an E.164 number, tenant ownership, capabilities, and an assigned AI agent. The current API supports manual registration of an already-owned Plivo number; automated Plivo number search/provisioning is a separate provider-management step.

## Production checklist

Before production traffic:

- Use a named HTTPS/WSS deployment, not a temporary tunnel.
- Store Plivo credentials in a secret manager in production.
- Configure Plivo V3 webhook signing and keep application signature validation enabled.
- Register only tenant-owned numbers and enforce tenant isolation.
- Keep outbound calling behind the global outbound feature flag and contact compliance gate.
- Verify consent/DNC policy for the target market before enabling campaigns.
- Run provider unit tests and a real inbound/outbound E2E call.
- Monitor webhook failures, WebSocket disconnects, provider API errors, latency, and Call Intelligence queue failures.
- Keep Twilio available as an independent provider; do not make Plivo a hard dependency for Twilio tenants.
- Complete retention/redaction and regulatory review before storing production transcripts or recordings.
